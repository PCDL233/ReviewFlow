## 二、行为变化（使用方需要知道）

1. **失败的语义更严格**：默认 `llm.onUnavailable=degrade` 仍会退回 mock，但报告与详情页会显示“模型不可用，本次仅完成静态分析”；需要硬失败时把配置改为 `fail`。
2. **同一问题只出现一次**：三个维度都命中时，报告保留一条并在 `agents` 中列出维度，统计不再 ×3。
3. **上下文行发现**：不在变更行、但文件内存在的问题会标 `lineScope=context`，`BLOCKER` 降级为 `WARNING`，不参与阻断；不再被静默丢弃。
4. **评分口径**：`riskScore` 现在是审查结论分（发现加权），`changeRiskScore` 是文件风险分；历史记录仍可读，旧的 `riskScore` 值语义不同。
5. **RAG 默认索引整个仓库**：`rag.knowledgeBasePaths` 默认从 `docs/` 改为 `.`，首次重建索引会遍历源码与文档（跳过 `node_modules/dist/.git` 等），可通过配置收窄。
6. **缓存失效更敏感**：模型、规则、自定义规则、阈值变化都会导致缓存未命中，避免复用旧口径结论。

## 三·补、M2：模型调用可观测、AI SDK transport 与 ReAct 工具

- `llm_calls` 表（迁移 v5）记录每次维度调用/自愈轮次：provider、model、status、round、prompt/completion/total tokens、estimated、latency、promptChars、fallbackUsed、attempts JSON。
- 流水线通过 `RunMetricsAccumulator.addLlmCall` 汇总，`report` 节点写入 `metrics.llmCalls`；`ReviewService` 在报告落库后写入 `llm_calls`（失败只记录日志，不影响报告）。
- 新增只读接口：`GET /api/reviews/:id/trace`（结论摘要 + 调用明细）、`GET /api/admin/llm-calls?limit=`（最近调用）。
- 新增 AI SDK transport（`llm.runtime` 默认 `ai-sdk`）：`generateText` 负责请求/`maxRetries`/`abortSignal`/原生 usage；`http` 保留为手写兼容回退。Anthropic 走 `@ai-sdk/anthropic`，OpenAI 兼容端点（含 Ollama/国内厂商）走 `createOpenAI().chat()`。
- 结构化输出（`llm.structuredOutput` 默认关）：开启后走 `generateObject` + `FindingsOutputSchema`，模型只填问题字段，agent/origin/误报由维度注入；有 ReAct 工具时自动回退文本模式。
- ReAct 工具：`review.toolCalling` 开启后注入 `read_file` / `list_symbols` / `search_repo` / `symbol_refs` 四个只读工具；执行器在 server 组合根绑定 `GitReader`，拒绝绝对路径/盘符/`..`，单次最多 200 行/60k 字符；`search_repo` 用 `git grep`（查询 ≤200 字符、每文件 ≤100 条）；`symbol_refs` 用 `git grep -w` 查标识符引用；`review.toolTimeoutMs` 对单次工具执行限时，超时按工具错误返回模型；AI SDK 用 `stopWhen(6)` 限制步数，`totalUsage` 汇总多步成本。
- 校验：`MockLanguageModelV2` 断言 usage/agent 强制/bad-response，并模拟一次 `read_file` 工具调用后求和两步 usage；server 单测覆盖路径越界、符号解析与 `git grep` 搜索。
- 节点检查点：迁移 v7 新增 `review_stages`，节点完成/失败时落库（起止时间、耗时、摘要）；`GET /api/reviews/:id/trace` 返回 `stages`，报告「调用明细」展示节点耗时；SSE 晚连接会先回放已落库节点事件；启动时清理无主检查点。
- 自动续跑：迁移 v9 `langgraph_checkpoints/langgraph_writes` + `SqliteCheckpointSaver` 持久化 LangGraph 状态；迁移 v10 `review_jobs` 记录运行中任务；进程重启后 `resumeInterrupted` 用同一 thread_id 恢复，网络/超时/限流错误同进程重试一次。
- 尚未做：自动断点续跑。

## 三·补二、M3：finding 生命周期与人工决策

- 迁移 v6：`reviews` 新增 `decision/decision_comment/decided_by/decided_at`；新增 `finding_comments` 表（评论人、用户名、正文、时间）。
- API：
  - `PATCH /api/findings/:id`：支持 `status`（open/acknowledged/fixed/ignored/false_positive）与 `isFalsePositive`；`false_positive` 自动同步误报标记；
  - `GET/POST /api/findings/:id/comments`：评论列表与新增（≤2000 字）；
  - `POST /api/reviews/:id/decision`：approve / request_changes / comment；
  - `GET /api/reviews/:id/decisions`：append-only 决策历史（迁移 v8）；
  - `GET /api/reviews/:id/compare?baseId=`：按发现指纹输出 added / resolved / persisting；
  - `GET /api/stats/rules`：按 `ruleId` 聚合命中数/严重度/误报数。
- 权限：沿用“本人或 admin”归属校验；越权统一 404。
- 前端：报告页发现卡新增处置状态下拉；页头新增“通过/要求修改”与决策标签。
- 校验：db 单测覆盖状态更新、误报同步、评论写入/读取、决策历史、规则聚合、删除级联；server 单测覆盖决策端点与 compare。

## 四、遗留项（下一轮，按优先级）

1. **自愈“否定”语义**：复核否定某条发现时，当前只能覆盖、不能从共享状态删除；需要引入 `removedFingerprints` 或让 validate/heal 返回替换集。
2. **finding 评论/负责人/决策、`parent_review_id` 写入、按规则/维度聚合**：列与基础 API 已就绪，人工处置闭环仍待 M3。
3. **工具超时**：同步工具无法在同线程中断；错误隔离与 ReDoS 预检已落地，真正超时需要 Worker 执行。
4. **ReAct 工具集**：已支持 `read_file` / `list_symbols` 与 6 步上限；`search_repo`/`symbol_refs`、工具级超时/预算、checkpoint 持久化属于后续 M2。
5. **前端闭环**：本轮只展示 LLM 状态、双评分、上下文行与维度标签；调用明细可视化、finding 状态/评论/重跑对比、Diff 行内卡片、高级运行选项仍待 M3/M4。
6. **配置生效矩阵**：`review.agents`、`cache.scope` 等新配置项尚未加入 schema；`maintainability` 仍在 schema 枚举中（为兼容旧配置保留，实际被过滤）。

## 五、兼容性

- 所有 shared schema 新增字段均为 optional；旧报告 JSON、旧 DB 行、旧客户端无需迁移即可解析。
- `report_json` 新增 `meta` 段；旧记录缺省时按列值/默认值展示。
- 现有 API 路径、退出码契约（0/1/2/3）、Hook/CI 响应形状未变；报告 summary/assessment 文案改为中文可读文本（依赖旧英文断言的测试已同步更新）。
- 新增配置项均有默认值，旧 `.ai-review.yml` 可直接加载。
